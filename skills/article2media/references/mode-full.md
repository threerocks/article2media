# 全文模式（-f，`--layout full`）：原文一字不改的长图

把**完整原文**排成一张（或几张）可连续阅读的长图。设计的对象是版式，不是文字：每一句原文按原顺序只出现一次，不摘要、不润色、不改标点、不补标题、不抽金句。生成图固定为 0；只呈现原稿自带的图片。

```bash
node ${CLAUDE_SKILL_DIR}/scripts/render.mjs <目录>/article.md --layout full            # 白底阅读面
node ${CLAUDE_SKILL_DIR}/scripts/render.mjs <目录>/article.md --layout full --theme quiet   # 用某个主题的颜色与字体
```

## 允许与禁止

| 属于排版（允许） | 属于改稿（禁止） |
|---|---|
| 原稿的标题、整段粗体小标题 → h1 / h2 / h3 | 摘要、润色、纠错、改标点、同义改写 |
| 粗体、斜体、引用、列表、代码、表格 → 对应语义 | 删节、合并段落、调换顺序 |
| 改字号、字重、颜色、留白 | 抽一句做题记、金句或结尾大字 |
| 段内换行保留为换行 | 原稿没有的标题、导语、小结、过渡句 |

## 它怎么保证一字不差

1. **锁定来源**：记录 article.md 的 SHA-256，渲染结束再算一次，变了就报错。
2. **原文块账本**（`full/ledger.json`）：每个可见文本块（段落、标题、列表项、表格单元、引用、代码、图注）一个编号，顺序即阅读顺序。
3. **解析覆盖**：账本拼起来的文字必须等于原文去掉 Markdown 符号后的文字，防止解析器漏段。
4. **页面读回**：浏览器里逐块读 `textContent`，必须与账本逐字相同；还检查块数、顺序、重复、嵌套、正文区有没有不属于任何原文块的字、视觉顺序有没有倒退。改一个字、调一次序、漏一块、重复一块，都会失败。
5. **实际字体**：报告正文、标题、小标题浏览器真正用上的字体（不只看 CSS 声明）。

## 阅读面（1080 px 成品）

- 正文 40 px / 1.9 行高，约 896 px 行宽；标题 80 / 54 / 44 px；表格 34、代码 32、图注 30。手机上约等于 14 px 的舒适字号。长图变高是放大文字的正常代价，不为压高度缩字。
- 默认白底 `#FFFFFF`、深中性黑 `#171717`，暗朱红只用于少量分隔与强调；标题和正文用京华老宋体（缺字时回退宋体）。
- 传 `--theme` 时换成主题的底色、文字色、主色和字体，字号下限不变。
- 超过约 14 800 px 时在**块与块之间**切成 `full-01.png`、`full-02.png`……，绝不切断段落；交付时说明分成了几张。

## 审片与交付

- 看 `full/review/slice-*.jpg`：重叠切片覆盖全部高度，逐段检查截断、遮挡、孤行、表格越界、配图是否完整。
- 交付报告：PNG 路径和尺寸、原文来源、原文块数量与全文校验结果（"45 / 45 块逐字一致"）、实际字体、生成图 0 张。
